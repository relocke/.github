# Security policy

Security issues should not be reported through public GitHub issues, discussions, or pull requests.

## Reporting a vulnerability

Use GitHub private vulnerability reporting on the affected repository when it is enabled. If it is unavailable, contact the ReLocke maintainers privately through the contact method published at [relocke.io](https://relocke.io).

Include, when possible:

- the affected repository, service, version, network, or deployment;
- a clear description of the vulnerability and its impact;
- reproducible steps or a minimal proof of concept;
- any conditions required for exploitation; and
- suggested mitigations or fixes.

Do not access data that does not belong to you, degrade production services, publish secrets, or perform social engineering. Give maintainers a reasonable opportunity to investigate and remediate before disclosure.

## Scope

Until a repository defines a more specific policy, this policy covers ReLocke-maintained source code, schemas, hosted services, build and deployment infrastructure, registry data, and official integrations.
